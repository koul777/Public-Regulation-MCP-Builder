# 초보자 규정 작성 사용성 검증 계획

기준일: 2026-08-30

## 목적

이 계획은 규정 작성 경험이 거의 없는 사용자가 별도 교육 없이 초안 작성의 첫
단계를 이해하고, 오류를 스스로 고치며, 결과를 공식 승인으로 오인하지 않는지를
검증한다. 기능 정확성·보안 테스트를 대체하지 않고 P0 출시 게이트에 사용자 관점의
증거를 추가한다.

## 대상 사용자와 전제

- 규정 제·개정 경험이 없거나 1회 이하인 행정·업무 담당자 5명 이상
- 시스템 개발에 참여하지 않았고 기존 화면을 외워서 사용하지 않는 사람
- 실재 기관 문서나 개인정보 대신 제공된 가상 기관·가상 규정 시나리오 사용
- 진행자는 조작 방법을 설명하지 않고, 사용자가 막힌 이유와 기대한 다음 행동만
  관찰 기록

## 핵심 과업

1. 원문 파일 없이 `위원회 운영 규정` 초안 공간을 만든다.
2. 목적, 적용 범위, 근거, 담당부서, 시행 예정일을 입력하고 조문 단계로 이동한다.
3. 의도적으로 남겨 둔 빈 필수 조문과 잘못된 내부 조문 참조를 검사 결과만 보고
   찾아 고친다.
4. 작성자 확인 목록을 완료하고 내용 확인을 요청한다.
5. 로컬 연습용 자체 확인의 의미를 설명한 뒤 동결하고 Markdown을 내려받는다.
6. 내려받은 파일이 기관 결재·법적 검토·RAG 승인·색인을 뜻하는지 질문에 답한다.

## 바로 실행할 가상 시나리오

모든 참여자에게 같은 과업지를 주되, 화면 조작 순서나 버튼 이름은 알려 주지 않는다.
진행자는 아래 값만 복사 가능한 별도 메모로 제공한다.

| 입력 항목 | 가상 값 |
|---|---|
| 기관 | 누리행정연구원(사용성 시험용 가상 기관) |
| 작성 방식 | 신규 제정 |
| 템플릿 | 위원회 운영 규정 |
| 규정명 | 정보공개위원회 운영 규정 |
| 목적 | 위원회의 구성과 심의 절차를 명확히 정한다. |
| 적용 범위 | 위원회 위원과 운영 담당부서에 적용한다. |
| 근거 | 정관 제10조 |
| 담당부서 | 운영지원부 |
| 시행 예정일 | 시험일 다음 달 1일 |

첫 검사 전에는 진행자가 지정한 필수 조문 하나를 비워 두고, 다른 시험용 조문 하나에는
`이 규정 제99조에 따른다`를 넣도록 요청한다. 어느 오류인지나 고치는 방법은 말하지
않는다. 검사 안내만 보고 빈 필수 조문을 자기 말로 완성하고 존재하는 조문을
가리키도록 수정하면 성공으로 기록한다.

충돌 복구 과업은 같은 가상 초안을 브라우저 창 A와 B에서 연 뒤 진행한다. A에서
저장하고, 오래된 B에서 서로 다른 한 문장을 입력한 뒤 저장을 시도하게 한다. B의
문장이 조용히 사라지지 않고 사용자가 이를 복사한 다음 `최신 개정 불러오기`로
복구하면 성공이다. 실제 기관 계정·문서·본문은 사용하지 않는다.

권장 세션은 사전 안내 5분, 무개입 과업 30분, 승인 의미 확인과 짧은 인터뷰 10분이다.
진행자는 제품 사용법을 가르치지 않으며, 안전 문제나 과업 중단 조건이 아니면 다음
행동을 대신 말하지 않는다.

## 통과 기준

| 지표 | P0 통과 기준 | 실패 시 우선 조치 |
|---|---:|---|
| 도움 없이 초안 공간 생성 | 참여자의 90% 이상 | 홈 진입점·템플릿 설명 수정 |
| 핵심 과업 전체 완료 | 참여자의 80% 이상 | 막힌 단계의 주 행동과 문구 단순화 |
| 현재 단계의 다음 행동 식별 | 각 단계 10초 이내, 80% 이상 | 주 버튼 1개와 단계 안내 재배치 |
| 린트 오류 수정 성공 | 오류별 80% 이상 | 위치명·수정 방법·해당 입력 연결 개선 |
| 오래된 화면 충돌 후 복구 | 2분 이내, 80% 이상 | 충돌 안내와 새로고침 동선 개선 |
| 공식 승인으로 오인 | 0명 | 상태명·경계 경고·출력물 문구 출시 차단 수정 |
| 다른 기관 초안 노출 | 0건 | 출시 차단, profile/tenant 범위 재검증 |

완료 시간은 학습 효과에 크게 좌우되므로 단독 합격 기준으로 쓰지 않는다. 대신
각 단계에서 멈춘 시간, 되돌아간 횟수, 오류 안내를 읽고도 진행하지 못한 원인을
함께 기록한다.

## 안전한 관찰 기록

- 프로젝트 UUID, 초안 본문, 법적 근거 원문, 로컬 경로는 사용성 기록에 남기지
  않는다.
- 기록 항목은 시나리오 ID, 단계명, 성공 여부, 경과 시간 구간, 도움 요청 유형,
  오인 여부로 제한한다.
- 화면 녹화가 필요하면 사전 동의를 받고 가상 데이터만 사용하며 검증 종료 후
  정한 보존 기간에 따라 삭제한다.
- 제품 telemetry를 새로 넣을 때도 opt-in과 보존 기간을 먼저 정하고, 작성 본문과
  오류 원문을 이벤트 속성으로 전송하지 않는다.

## 접근성·이해도 점검

- 키보드만으로 기관 선택, 초안 생성, 입력, 검사, 내보내기까지 진행한다.
- 경고를 색상만으로 구분하지 않고 `오류`, `경고`, `안내` 텍스트와 함께 제시한다.
- 버튼 이름만 읽어도 결과를 예측할 수 있는지 확인한다.
- `내용 동결`, `개정본`, `근거`, `적용 범위`를 참여자가 자기 말로 설명하게 한다.
- 200% 확대와 좁은 화면에서 필수 안내와 주 버튼이 잘리거나 순서가 바뀌지 않는지
  확인한다.

## 단계적 출시

1. **내부 데스크 테스트**: 가상 데이터로 결정론적 테스트와 2인 인지 walkthrough를
   수행한다.
2. **초보자 파일럿**: 위 조건의 참여자 5명 이상으로 과업 성공률과 오인을 측정한다.
3. **제한된 로컬 배포**: 한 기관의 교육 환경에서만 기능 플래그를 켜고 문의 유형을
   수집한다.
4. **P0 판정**: 보안·무결성·공개 저장소 위생 게이트와 이 문서의 통과 기준을 모두
   만족할 때만 기본 로컬 기능으로 유지한다.
5. **보호 배포 판정**: 인증, tenant 격리, 계정 분리, 중앙 감사와 보존·폐기 절차를
   별도로 검증한 뒤 명시적으로 opt-in한다.

## 회귀 증거

자동화 증거는 다음을 최소 세트로 보존한다.

- 템플릿·린트·상태 전이 단위 테스트 결과
- Streamlit 시작점, 다음 행동, 경계 문구와 기관 전환 초기화 테스트 결과
- profile/tenant 교차 접근, stale revision, 4-eyes와 변조 거절 테스트 결과
- 기관 삭제 시 작성 초안까지 범위대로 삭제되고 다른 기관·tenant는 보존되는 결과
- 전체 `unittest`, 배포 아카이브 build, 공개 릴리스 위생 감사 결과

사람 사용성 결과는 개인 식별 없이 날짜, 참여자 수, 과업별 성공률, 발견된 오인과
조치만 릴리스 기록에 요약한다.

## 관찰 기록 양식

참여자마다 아래 표를 복사해 사용한다. 자유 서술에는 사용자가 입력한 초안 문장을
옮기지 않고, 화면 요소와 막힌 이유만 적는다.

| 항목 | 기록 값 |
|---|---|
| 익명 참여자 번호 | `P01` 형식 |
| 규정 작성 경험 | 없음 / 1회 |
| 사용 환경 | OS·브라우저·화면 확대율·키보드 전용 여부 |
| 초안 공간 생성 | 성공/실패, 30초 미만·30~60초·1분 이상 |
| 기본정보 완료 | 성공/실패, 도움 요청 유형 |
| 린트 오류 2건 수정 | 각 오류 성공/실패, 안내를 이해하지 못한 용어 |
| 검토·동결·Markdown | 성공/실패, 잘못 누른 전이 버튼 |
| 충돌 복구 | 성공/실패, 1분 미만·1~2분·2분 이상 |
| 공식 승인 의미 질문 | 정확/오인, 참여자의 설명을 식별 정보 없이 요약 |
| 접근성 관찰 | 초점 순서, 잘린 안내, 색상 외 구분, 읽기 어려운 용어 |
| 진행자 개입 | 없음 / 질문 되묻기 / 과업 중단 |

진행자는 시작 전에 “법령 지식”이 아니라 “화면을 혼자 따라갈 수 있는지”를 보는
시험이라고 알린다. 참여자가 2분 이상 같은 단계에서 멈추면 정답을 알려 주지 않고
무엇을 기대했는지만 질문한 뒤 과업을 중단 또는 계속으로 기록한다.

## 파일럿 판정 기록

파일럿 종료 뒤 다음 의사결정을 한 장으로 남긴다.

- 실행일, 참여자 수, 사용한 빌드 식별자
- 과업별 성공률과 다음 행동 10초 내 식별률
- 공식 승인 오인 수, 교차 기관 노출 수, 삭제 잔존 수
- 키보드 전용·200% 확대 결과
- 발견별 심각도, 담당자, 목표 수정일, 회귀 테스트 링크
- `GO`, `조건부 재시험`, `NO-GO` 중 하나와 판정자

`조건부 재시험`은 일반 출시 허가가 아니다. 통과 기준 미달 항목을 수정한 뒤 영향을
받은 과업과 오인 질문을 새 참여자로 다시 실행해야 한다.
