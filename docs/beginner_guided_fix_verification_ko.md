# 초보자 클릭 안내 수정 후 실제 실행 검증

2026년 9월 29일, 새 빈 저장소와 합성 장비 대여 규정 DOCX로 처음부터 다시 실행했다.
안내에 나온 실제 입력·버튼만 사용해 8개 청크를 대조하고 승인·색인한 뒤,
독립 Qwen 챗봇에서 세 질문의 답변과 근거를 확인했다. 이번 경로는 중간 복구 없이 완료했다.

[실제 실행 발췌 영상 MP4](https://raw.githubusercontent.com/koul777/Public-Regulation-MCP-Builder/9283434c6fedb20fd2b05421e838f600a5784193/docs/assets/guided-fix-live-demo.mp4)
는 원문 대조, 검수 확인, 챗봇 실행·이동, 답변과 근거 부족 응답 장면을 담았다.
대기 구간을 생략하고 일부 구간은 1.25–2배속으로 편집했다. 실제 화면의 결과를 바꾸거나
성공 상태를 삽입하지 않았다. 모든 조항의 클릭과 대기 시간을 보여 주는 무편집 영상은 아니다.

## 수정 내용

| 발견한 문제 | 수정과 확인 |
| --- | --- |
| 검수 안내가 원문과 최종본을 어둡게 가림 | 검수 단계는 본문 안에 안내를 배치. 안내를 멈추지 않고 주변 원문을 읽고 스크롤·클릭할 수 있음 |
| 긴 원문을 가로로 스크롤해야 함 | 원문·전처리 미리보기·승인 최종본에 줄바꿈 적용. 8개 행의 원문에 가로 넘침 없음 |
| 챗봇 실행 버튼에 자동 안내가 없음 | 실행 버튼에서 준비된 앱의 이동 링크로 안내가 이어짐 |
| 실행 후 빌더 완료 표시가 이전 상태에 머묾 | 앱의 정상 응답 확인 직후 화면 갱신. 별도 새로고침 없이 `3 / 3 완료` |
| AI 검수가 꺼져 있어도 AI 확인이라고 표시 | 일반 검수 항목 확인 문구로 변경. 기존 검수·승인 감사 기록은 유지 |
| 같은 조문이 인용 표에 두 번 표시됨 | 같은 문서·버전의 동일한 공개 인용 행만 합침. 내부 근거와 서로 다른 문서·쪽·인용문은 보존 |
| 정보가 없다는 답변에 무관한 조문을 붙임 | 명시된 근거 부족 표현을 답변 유보로 처리하고 인용 제거. 모델 지시에도 유보 계약 명시 |

## 실제로 진행한 순서

1. 초보 안내를 시작하고 새 가상 기관 생성.
2. 합성 DOCX를 업로드하고 인식 정보를 확인한 뒤 전처리 실행.
3. 표·전문·제1조부터 제5조·부칙의 8개 행을 원문과 최종본으로 대조.
4. 표시된 검수 항목 판단과 조항별 확인·승인 동의 체크를 직접 클릭.
5. 최종 확정·승인하고 색인을 눌러 실제 Qwen3 Embedding 0.6B, 384차원 벡터 8개 생성.
6. 안내된 Qwen 실행 버튼과 새 창 이동 링크를 클릭. 빌더 `3 / 3 완료` 확인.
7. 챗봇 안내에 따라 기관·규정 선택, Ollama 연결 확인. 첫 연결 시도 성공.
8. 세 질문을 입력하고 전송 버튼을 눌러 답변·인용과 원문을 대조.

검수 동안 안내를 잠시 멈출 필요가 없었다. 추가 질문은 답변 안내의 **안내 접고 직접 하기**를
누른 뒤 전송했다. 승인 상태나 완료 표시를 직접 주입하지 않았고 API로 작업을 대신하지 않았다.
저장소의 읽기 전용 사후 확인에서 검수 완료 8개, 미검수 승인 0개, 실제 색인 작업 1개,
승인 벡터 8개를 확인했다. 브라우저 오류와 화면 예외는 0건이었다.

## 질문·답변·근거 대조

| 질문 | 실제 답변 요지 | 화면의 근거 |
| --- | --- | --- |
| 대여 신청 기한과 승인 통지 기한 | 사용일 3근무일 전 신청, 접수 후 1근무일 이내 통지 | 제2조·제3조, 1쪽 |
| 반납 기한과 기록 보관 기간 | 사용 종료일 다음 근무일 반납, 기록은 2년 보관 | 제4조·제5조, 1쪽. 각 1행 |

## 자동 검사

```powershell
python -m unittest discover -s tests -v
node tests/browser/beginner-tour.cjs
python -m build --sdist --wheel
python scripts/audit_release_hygiene.py --workflow-scope available --include-untracked --include-source-path-scan
```

브라우저 검사는 Playwright와 Chromium이 필요하다. 원문 가림과 키보드 이동,
다시 뜨는 일반 안내, 채팅 전송 버튼 가림을 검사한다. Python 회귀에는 정상·실패·대기 중
챗봇 실행 상태, 중복 인용 보존 경계, 모델이 잘못 붙인 근거 부족 인용을 포함했다.
집중 회귀 58개, 문서·미디어 배포 검사 3개, 안내 브라우저 검사, sdist·wheel 빌드,
공개 소스 위생 검사를 통과했다. 첫 전체 검사에서는 기존 README의 배포 문서 누락과
상대 미디어 링크 두 건이 실패해 MANIFEST와 공개 URL을 고쳤으며, 해당 세 검사는
수정 후 모두 통과했다. 최종 전체 검사 결과는 PR 검증란에 기록한다.

## 검증 범위

- Windows 소스 실행 환경, Kordoc 4.16.0, 실제 로컬 Ollama와 Qwen3 8B를 사용했다.
  AI 추가 검수와 Qwen3 4B 정밀 감사는 끈 기본 경로다. 검색은 BM25/lexical 경로였다.
- 파일은 실제 브라우저 업로드 입력으로 전달했다. Windows 파일 선택창 조작과 기본 브라우저
  자동 실행은 제외하고, 화면의 이동 링크로 같은 headless Chromium에서 새 창을 열었다.
- 모든 입력은 합성 규정이었다. 공개 저장소에는 선별한 합성 화면만 추가하고 원본 업로드,
  실행 저장소·저널·전체 추적과 로컬 경로는 포함하지 않았다.
- 이번 검사는 이미 필요한 패키지와 모델이 설치된 환경이다. 새 Windows 설치의 패키지 누락,
  모델 최초 다운로드·연결 시간 초과, 다른 문서 형식과 외부 MCP 앱의 전체 검증은 포함하지 않는다.
- 근거 부족 표현을 보수적으로 유보 처리하는 수정이다. 모든 자연어 답변의 의미상 정확성을
  자동으로 증명하는 기능은 아니며, 사용자는 답변의 근거를 계속 확인해야 한다.
