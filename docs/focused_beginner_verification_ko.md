# 조항별 초보자 안내와 AI 수정안 표시 검증

검증일: 2026년 9월 29일. 모든 입력은 합성 규정이며 실제 기관 자료를 사용하지 않았다.

## 변경한 동작

초보자 모드는 설정·작업 저장·규정 목록을 접고 한 번에 한 조항의 원문, 편집 가능한 최종본,
AI 검수 의견을 보여 준다. 표시된 검수 항목을 직접 판단하고 **원문·최종본 확인 완료 · 다음**을
누르면 다음 조항이 열린다. **확인한 조항 다시 검토하기**에서 이전 조항을 다시 열면 확인이
해제되며, 편집 초안과 검수 판단은 유지된다. 모든 조항을 확인한 뒤 최종 승인 버튼이 나타난다.

전처리 시작 버튼은 파일 정보를 확인한 뒤 나타나고, 완료 후에는 검수 이동 버튼을 먼저
보여 준다. AI 추가 검수 결과도 같은 비교 화면에서 확인한다. 사용할 수 없는 버튼은 클릭
안내 대상으로 선택하지 않는다. 검수·최종 승인 안내는 본문에 표시해 다른 조항을 다시
열거나 원문을 읽는 동작을 가리지 않는다. 일반 모드의 기존 일괄 작업과 감사 기록은 유지한다.

![한 조항씩 원문과 최종본을 비교하는 화면](https://raw.githubusercontent.com/koul777/Public-Regulation-MCP-Builder/8a7978f22adabef5cdd2b68ccdc7f06f76d044a0/docs/assets/focused-beginner-review.png)

## AI 수정안이 검증 칸에서 빠지던 원인과 수정

검증 칸이 `metadata.agent_review_findings`만 읽고 저장된 `ai_preprocessed_text`를 읽지 않아,
예전 실행에서 저장된 AI 수정안이 있어도 보이지 않았다. 이제 제안 전문과 추가·삭제 차이를
표시한다. 조항 메타데이터에 검수 의견이 없으면 실행 요약에서 같은 조항 ID의 의견만 찾아
표시한다. 지적 없음, 미실행, 결과 미저장 상태도 구분한다.

**AI 제안을 최종본에 반영**은 현재 편집 초안을 제안으로 바꾸는 명시적 동작이다. 승인·색인은
실행하지 않으며 기존 확인을 해제해 원문과 다시 대조하게 한다. 문서에서 온 HTML은 차이
표시에 넣기 전에 이스케이프한다. 긴 본문은 줄 단위 차이를 사용한다.

![원문, 반영한 편집 초안, 저장된 AI 제안과 변경 표시](https://raw.githubusercontent.com/koul777/Public-Regulation-MCP-Builder/8a7978f22adabef5cdd2b68ccdc7f06f76d044a0/docs/assets/ai-proposal-visible.png)

위 AI 화면은 띄어쓰기 수정안을 미리 저장한 별도 합성 데이터 검사다. 외부 AI 제공자를
호출해 수정안을 생성한 시연이 아니다. 반영 전에는 편집 칸이 원문을 유지했고, 클릭 후에만
바뀌었으며 승인 기록은 0건이었다. 현재 AI 추가 검수는 주로 의견을 생성한다. 저장된 수정안이
없는 조항에 새 수정안을 만들어 표시하지 않는다.

## 표·조문 파싱 보완

- DOCX 셀 안의 중첩 표를 문단 순서대로 읽고, 세로 병합 셀의 원문 중복을 방지했다.
  물리 셀의 행·열, 가로 병합 폭, 세로 병합 상태, 중첩 표 수를 파서 메타데이터에 보존한다.
- 콘텐츠 컨트롤 안에 있는 본문 조문을 빠뜨리지 않도록 본문 컨테이너를 순서대로 순회한다.
- `한다.제2조(신청)`처럼 공백 없이 붙은 조문을 분리한다. 본문 중 `제2조(승인)에 따라`라는
  인용은 새 조문으로 분리하지 않는 회귀 검사를 함께 유지했다.
- 중첩·병합 표의 내용 추출이 성공해도 셀 관계는 원문과 대조하도록 검수 플래그를 남긴다.
  파이프라인 버전을 바꿔 이전 파싱 결과를 새 결과로 재사용하지 않도록 했다.

모든 문서·표의 완전한 정확성을 보장하는 변경은 아니다. 이미지 표, 복잡한 배치, 머리말·
각주 등의 기존 제한과 검수 플래그는 유지하며, 불확실한 결과는 원문을 확인해야 한다.

## 실제 브라우저 실행

Windows 소스 실행 환경, Kordoc 4.16.0, 실제 임베딩 모델과 Ollama `qwen3:8b`를 사용했다.
AI 추가 검수와 Qwen 정밀 감사는 끈 기본 경로다. Playwright는 표시된 입력·버튼을 조작했고
원문·편집 칸을 읽어 대조했다. 승인·색인 상태를 주입하거나 모델 답변을 대체하지 않았다.

1. 새 기관 생성 → 가상 DOCX 업로드 → 자동 인식 정보 확인 → 전처리 완료 화면.
2. 8개 조항·표를 한 개씩 대조. 표의 3행·2열 문구와 기한을 비교하고 나머지 본문은 추출
   원문과 편집 칸을 대조했다. 경고는 내용을 읽고 직접 판단한 뒤 다음 버튼을 눌렀다.
3. 확인한 조항을 다시 열어 최종 승인 버튼이 사라지는 것을 확인하고 다시 확인했다.
4. 최종 승인 후 승인 기록 1건, 실제 의미 임베딩 벡터 8개, 색인 완료 작업 1건을 확인했다.
5. Qwen 실행 → 새 창 이동 → 기관·규정 선택 → 모델 연결 확인 → 질문·근거 확인까지 진행했다.
   “장비 대여 신청은 언제까지 해야 하나요?”에 **사용일의 3근무일 전**이라는 답변과
   **제2조 대여 신청, 원문 1쪽**의 근거가 표시됐다. 마지막 실행의 답변 완료 표시는 8.2초였다.

최종 실행의 브라우저 오류와 화면 예외는 0건이었다. 앞선 실행에서는 모델 첫 응답 점검이
실패했고, 화면의 연결 확인 버튼으로 재점검한 뒤 질문에 성공했다. 그 실패를 숨기지 않고
재시도 경로로 확인했다. 필요한 패키지와 모델이 이미 있는 PC이며 새 PC의 전체 다운로드,
Windows 파일 선택창 조작, 외부 MCP 앱의 전체 연결 검증은 이번 범위에 포함하지 않았다.

## 자동 검사

새 회귀는 저장된 수정안 표시·명시적 반영·확인 해제·HTML 이스케이프·조항 ID별 의견 선택,
조항별 진행·재검토·승인 분리, DOCX 중첩·병합·컨테이너, 조문 경계, 이전 캐시 배제를 다룬다.
AI 표시 검사 모음을 GitHub 회귀에도 포함했다. 승인 화면 AppTest는 임베딩 추론만 고정된
벡터로 대체하며 실제 승인·저널·색인 경로를 실행한다. 위 브라우저 실행은 실제 모델이다.

- `python -m unittest discover -s tests -v`: 첫 실행 3,795개 중 기존 화면 문구·들여쓰기 문자열
  검사 2건이 실패했다. 새 동작에 맞게 수정했고, README의 기존 단계 문구 기대값도 갱신했다.
  수정한 화면·README·배포 문서 계약 66개와 표시·안내 집중 검사 72개가 통과했다.
  최종 전체 결과는 병합 PR의 검증란에 기록한다.
- Chromium 안내 제어기 검사: 통과. 비활성 대상 제외, 모바일, 키보드, 재렌더링,
  접힌 항목, 중지·재개, 자동 승인 없음, 질문 전송 가림 방지를 포함한다.
- `python -m build --sdist --wheel`: 통과.
- 공개 파일 위생 검사(미추적 파일·소스 경로 검사 포함): 통과.
