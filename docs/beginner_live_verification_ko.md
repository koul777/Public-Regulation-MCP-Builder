# 가상 규정으로 실행한 초보자 클릭 검증

> 이 문서는 첫 실행의 실패·복구 기록입니다. 원문 가림, 챗봇 실행 안내, 완료 표시,
> 중복·근거 부족 인용은 이후 수정했습니다. 최신 결과는
> [수정 후 처음부터 다시 실행한 검증](beginner_guided_fix_verification_ko.md)을 참고하세요.

2026년 9월 29일 Windows 소스 실행 환경에서 실제 Streamlit 화면을 Playwright
Chromium으로 조작했다. 기관 생성부터 업로드, 조항 검수, 승인·색인, 독립 Qwen
챗봇 실행과 연속 질문까지 진행했다. 실제 기관 자료 대신 제1조부터 제5조,
부칙과 표 하나가 있는 합성 DOCX를 사용했다.

## 확인 결과

| 단계 | 실제 확인한 결과 |
| --- | --- |
| 기관과 파일 | 안내에 따라 기관을 생성하고 파일 입력으로 합성 DOCX 업로드 |
| 정보 확인 | 인식 정보 확인 전 전처리 버튼 비활성, 확인 뒤 활성 |
| 전처리 | Kordoc 4.16.0이 표 1개 추출, 본문·표·부칙 등 8개 청크 생성 |
| 조항 검수 | 각 검수 항목 판단, 검수 확인, 원문·최종본 대조를 직접 수행 |
| 안내 멈춤 | 제4조에서 잠시 멈춘 뒤 확인을 클릭해도 안내가 다시 열리지 않음. 이어 보기에서 제5조로 안내 |
| 최종 승인 전 | 저장소에서 승인 청크 0개, 승인 저널 0개, 색인 작업 0개 확인 |
| 최종 승인 | 최종 확정 버튼을 누른 뒤 승인 청크 8개와 승인 저널 생성 |
| 색인 복구 | 누락된 임베딩 패키지 설치 후 화면의 재등록 버튼으로 8개 등록 |
| 실제 임베딩 | Qwen3 Embedding 0.6B, 384차원, 의미 임베딩 8개 모두 승인 상태 |
| 챗봇 진입 | 빌더 실행 버튼으로 별도 앱 시작, 링크로 이동 후 기관·규정 선택 |
| Qwen 연결 | 첫 연결 확인 실패 후 재시도 성공. 성공 전에 질문 입력 비활성 |
| 연속 질문 | 실제 Qwen3 8B 답변과 근거 인용, 근거 부족 응답까지 확인 |

## 질문과 근거 대조

| 질문 | 실제 답변 요지 | 확인한 근거 |
| --- | --- | --- |
| 일반 휴가 신청 기한 | 시작일의 5근무일 전까지 제출 | 제2조, 원문 1쪽 |
| 긴급 휴가 절차와 기록 보관 기간 | 먼저 담당자에게 전화, 2근무일 이내 신청서 보완, 기록은 3년 보관 | 제3조·제5조, 원문 1쪽 |
| 규정에 없는 휴가 지원금 액수 | 승인된 규정 근거에서 확인할 수 없음 | 인용 없음 경고와 해당 안내 표시 |

앞의 두 답변은 실행 추적에서도 `grounded_local`, `ollama`, `qwen3:8b`로
확인했다. 세 번째 답변은 `abstained`였다. 숫자와 조문을 원문 및 화면의 인용
표와 대조했다. 두 번째 답변의 인용 표에는 본문 제5조와 표에 연결된 제5조가
각각 표시되어 같은 조문명이 두 번 나왔다.

## 발견한 문제와 조치

- **추가 질문 전송 버튼 가림 — 수정 및 재검증 완료.** 안내를 접었을 때 오른쪽
  아래 안내 막대가 채팅 전송 버튼을 덮었다. 입력창 높이에 맞춰 막대를 위로
  옮기고, 여러 줄 입력·화면 크기 변경·입력창 재생성을 추적하도록 수정했다.
  수정 전 실패하는 브라우저 회귀 검사를 추가했으며, 수정 후 통과했다.
  실제 챗봇에서도 안내를 켠 상태로 전송 버튼을 눌러 두 차례 추가 질문에 성공했다.
- **검색 등록 패키지 누락 — 이번 실행 환경 복구 완료, 설치 안내 보완 필요.**
  기본 가상 환경에 `torch`, `transformers`, `sentence-transformers`가 없어
  첫 색인이 500 오류로 끝났다. 승인은 저장되어 있었다. CPU PyTorch와
  프로젝트 범위에 맞는 sentence-transformers를 설치한 뒤 재등록에 성공했다.
  오류 직후 승인 숫자는 이전 값으로 남았고, 규정 열기를 다시 누르자
  승인 완료·색인 대기 안내와 재등록 버튼이 나타났다. 패키지 사전 점검과
  오류 직후 상태 갱신은 추가 개선 대상이다.
- **원문 대조 중 본문 가림 — 추가 개선 필요.** 체크 항목만 강조할 때 원문과
  최종본이 어둡고 흐리게 보였다. 안내 잠시 멈춤으로 내용을 읽고 이어갈 수
  있었지만, 대조 영역도 함께 보이도록 하는 편이 낫다.
- **빌더의 챗봇 실행 단계 — 추가 개선 필요.** 실행 버튼과 순서 설명은 보였지만
  해당 버튼을 가리키는 자동 강조 안내가 없었다. 독립 Qwen 앱에 들어간 뒤에는
  기관·규정·연결·질문·근거 안내가 이어졌다.
- **모델 최초 연결 대기 — 재시도로 복구.** 첫 연결 확인은 응답 대기 시간을
  넘겼고 두 번째는 성공했다. 실패를 연결 완료로 표시하거나 질문을 허용하지 않았다.

## 검증 범위와 한계

- Kordoc, 승인·색인, Ollama 답변은 대체 함수 없이 실제 실행했다. 별도 임시
  저장소만 사용했으며 기존 운영 자료에는 쓰지 않았다.
- 파일 입력은 브라우저의 실제 업로드 입력으로 전달했다. Windows 파일 선택창
  조작은 포함하지 않았다. OS의 기본 브라우저 자동 열기는 테스트 기록으로
  연결하고, 실제 화면의 이동 링크를 눌러 같은 headless 브라우저에서 확인했다.
- AI 추가 검수와 Qwen3 4B 정밀 근거 감사는 끈 기본 경로를 사용했다.
  챗봇 검색은 기본 BM25/lexical 경로이며, 의미 벡터를 만들었다는 사실이 이번
  질문에서 벡터 검색·재랭커까지 사용했다는 뜻은 아니다.
- 한 개의 합성 DOCX와 한 로컬 환경의 결과다. 모든 기관 규정·HWP/HWPX/PDF,
  새 Windows 설치, portable 실행판, 외부 MCP 앱 전체에 대한 통과 선언은 아니다.
- 실패·복구를 포함한 화면과 실행 기록은 로컬에 보관했다. 원본 업로드와
  실행 저장소, 전체 추적 데이터는 공개 저장소에 포함하지 않았다.

## 수정 회귀 검사

```powershell
node tests/browser/beginner-tour.cjs
python -m unittest discover -s tests -p test_beginner_tour.py -v
python -m unittest discover -s tests -p test_qwen_chat_app.py -v
python -m build --sdist --wheel
python scripts/audit_release_hygiene.py --workflow-scope available --include-untracked --include-source-path-scan
```

브라우저 검사는 Playwright 및 Chromium 설치가 필요하다. 새 전송 버튼 회귀와
기존 안내 브라우저 시나리오, 관련 Python 테스트 33개, 패키지 빌드와 공개 소스
위생 검사를 통과했다. 이 소규모 화면 수정에서 전체 unittest 모음을 다시
실행한 것은 아니다.
