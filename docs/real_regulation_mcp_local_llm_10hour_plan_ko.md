## 1. 목표와 완료 범위

실제 규정 파일을 전처리하고, 유효한 기존 승인 저널과 해시가 확인된 색인으로 실제 MCP 클라이언트와 로컬 LLM에 질의한다. 신규 전처리 결과는 사람 검토 전까지 승인·색인하지 않는다. 기존 시스템 승인에 검토 생략 사유가 있으면 이를 사람 검토 완료로 바꾸어 표시하지 않는다. 같은 문서·질문·모델 조건에서 변경 전후를 비교하고, 측정된 주요 실패 원인을 수정한다.

10시간의 결과물은 재실행 가능한 통합 회귀 도구, 개선 코드와 집중 테스트, 검증한 로컬 MCP 번들, 로컬 QA 실행 설정, 전후 비교 보고서다. 설치된 모델을 연결하며 모델 학습·가중치 제작은 범위에 포함하지 않는다.

운영 경로는 다음과 같이 검증한다.

1. 원본 → 전처리 → 검수·승인 확인 → 승인된 색인.
2. 같은 승인 색인 → 실제 MCP subprocess → initialize·tools/list·검색·원문 조회.
3. 같은 승인 색인 → 실제 로컬 API `/api/rag/chat` → Ollama 답변 → 근거·인용 검증.
4. 대표 질의는 MCP에서 실제로 받은 근거를 기존 context·답변·인용 정책에 전달하는 연계 검사도 수행한다. 이것은 회귀 도구의 검증 경로이며 기존 운영 API와 구분해 기록한다.

## 4. 실제 문서와 정답셋

### 문서 선정과 승인

- 장문 규정집, 개별 규정, 복잡한 표·별표, 부칙·개정 이력이 있는 PDF를 포함한다. 이미지/OCR 문서는 실제 보유 및 파서 지원 여부를 확인해 별도 분류한다.
- 원본은 그대로 두고 공개 checkout 밖의 비공개 실행 디렉터리에 선택한 입력과 필요한 런타임 snapshot을 복사한다. 원본·실제 질문·답변·실행 보고서는 공개 소스에 추가하지 않는다.
- 기존 승인 저널과 원문·청크 해시가 일치하는 자료부터 사용한다. 승인 기록을 복사하는 것만으로 재전처리된 다른 청크를 승인된 것으로 간주하지 않는다.
- 신규 입력 또는 변경된 파싱 결과는 검수 대기 상태로 남긴다. 사람 승인이 없는 항목은 승인 거부 회귀에 사용하고, 답변 가능 경로는 유효한 기존 승인 자료로 계속 진행한다.
- HWP/HWPX/DOCX는 검증된 실제 원본이 확보된 경우만 실문서 결과에 포함한다. PDF에서 변환한 자료나 합성 fixture는 별도 표시한다.

## 6. 실제 LLM 실행과 성과 판정

### 재현 조건

commit, 원본·청크·승인 snapshot·색인·질의셋 해시, tenant/profile/권한, 모델 tag와 digest, prompt 버전, 생성 옵션, 장비, timeout을 실행 manifest로 고정한다. 모델 목록 응답, HTTP 200 또는 `answer_model` 필드 하나만으로 실제 모델 답변 성공을 판단하지 않는다.

실제 Ollama 호출 이벤트와 반환값, 최종 `answer_mode`, fallback·기권 여부를 연결해 기록한다. 정상 답변, 안전한 추출식 fallback, 정당한 기권, 생성 오류를 각각 집계한다. 모델을 호출했더라도 최종 응답이 발췌문이면 모델 생성 성공률에 넣지 않는다.

실제 요청의 temperature·seed·출력 제한을 확인하고 고정한다. 검색, context 구성, 모델 적재·생성, 주장 감사, 인용 검사 시간을 나누어 기록한다. cold와 warm, 첫 토큰 시간과 전체 응답 시간은 측정 가능한 범위에서 구분하며 비스트리밍 응답의 전체 시간을 첫 토큰 시간으로 표시하지 않는다.

핵심 10문항은 3회 반복해 결과 변동과 p50/p95를 기록한다. 나머지는 동일 조건으로 기준선·개선본을 비교한다. 모델 자체의 채점을 유일한 정답 판정으로 사용하지 않고 원문에 고정된 사실·수치·조건 및 인용 근거로 검증한다.

| 기권·차단 | 정답셋의 근거 없음·권한 밖 질의 100% 기대 기권/차단 |
| 개선 효과 | 개발셋 실패가 있으면 실패 수 20% 이상 감소 목표. 보류셋에서 새 중대 오류 0건 |
| 속도 | 품질 유지 조건에서 측정된 주 병목 시간 20% 감소 목표. 같은 모드 전체 p95가 기준선보다 10% 넘게 악화되면 채택 보류 |
| 회귀·배포물 | 전체 테스트·build·위생 검사 통과. 필수 실문서/모델 검사 누락은 통과로 집계하지 않음 |

2026-10-22: 이 표에서 기계로 판정할 수 있는 항목은 `scripts/policies/real_regulation_kpi_guardrails.v1.json`과 `scripts/check_real_regulation_kpi_guardrails.py`로 옮겼다. 등급과 판정 규칙은 [실제 규정 회귀 문서](real_regulation_regression_ko.md)의 "KPI 가드레일"을 따른다.

기준선 오류가 0건이면 오류 감소 목표를 적용하지 않고 정확도 유지와 지연 개선을 평가한다. 표본이 작으면 비율과 함께 정확한 성공/실패 건수를 쓴다. 모든 품질 조건을 지키면서 속도를 개선할 수 없으면 품질을 우선하고 속도 목표 미달을 기록한다.

## 7. 측정 결과에 따른 개발 분기

- **원문 손실·경계 오류가 주원인:** 조문/별표 경계, 표의 행·열·단위 보존, 잘림 검출을 수정하고 해당 파서 회귀를 추가한다. 변경된 청크는 재승인 대상이다.
- **검색 누락이 주원인:** 정확한 조문 locator, 후보 순위, 동의어·띄어쓰기, context 선택을 비교한다. 설치된 임베딩 모델 사용은 기존 방식보다 낫다는 측정 근거와 분리 색인 검증을 확보할 수 있을 때만 검토한다.
- **근거는 맞지만 답변이 틀림:** 조건·예외 누락, context 잘림, 수치·단위 변형, 인용 불일치를 먼저 고친다. 단순 답변 길이 증가는 개선으로 보지 않는다.
- **지연이 주원인:** 모델 적재, 질의 분석, 생성, 주장 감사 중 가장 느린 단계부터 개선한다. 모델 교체/감사 모드 변경은 다른 조건으로 기록하고 동일 품질 기준을 적용한다.
- **승인 가시성 또는 번들 결함:** 이를 먼저 해결한다. 승인 검사를 TTL로 늦추거나 strict 색인 조건을 완화해 성능 통과를 만들지 않는다.

## 8. 장애·시간 초과 대응

- 모델 실행 불가: 설치·endpoint·메모리 문제 진단에 최대 30분을 쓰고, 이후 MCP·검색·통합 도구 작업을 진행한다. 실제 LLM 결과는 미완료로 남기며 mock/fallback으로 대체 통과시키지 않는다.
- 유효한 승인 자료 부족: 기존 승인 snapshot으로 가능한 범위만 검증한다. 신규 자료의 파싱·차단 검사는 계속하고 사람 검토가 필요한 청크와 이유를 별도로 인계한다.
- 정답셋·실제 포맷 부족: 위 최소 표본으로 축소하거나 해당 형식을 미검증으로 남긴다. 빠진 실문서 fixture를 합성 자료로 가장하지 않는다.
- 반복 실패: 같은 명령의 무한 재실행 없이 원인을 분류한다. 외부 의존성이 막으면 독립 작업으로 이동한다.
- 10시간 종료: 실행 프로세스와 임시 자원을 정리하고 복구 가능한 상태로 종료한다. 미달 목표·검토 대기를 숨기지 않는다. 모든 완료 조건을 먼저 달성하면 일찍 종료하고 실제 소요 시간을 쓴다.

## 9. 최종 검증과 산출물

저장소 루트에서 다음 필수 명령을 실행한다. 비공개 로그 경로는 세션 환경으로 주입하며 문서·질의·모델 응답 원문을 공개 PR 본문에 붙이지 않는다.

```powershell
python -m unittest discover -s tests -v
python -m build --sdist --wheel
python scripts\audit_release_hygiene.py --workflow-scope available --include-untracked --include-source-path-scan
```

코드 변경과 최종 비교 조건이 동일한지 확인하고 다음을 인계한다.

- 공개 소스: 통합 실행기, 필요한 개선 코드, 대응 집중 테스트, 실행 안내.
- 비공개 실행 자료: `session.json`, `corpus-manifest.json`, 개발/보류 query spec, 기준선·개선본 JSON, 실제 답변·검증 trace, 실패 사례 비교.
- 비공개 실행 번들: 승인된 MCP runtime ZIP, 로컬 MCP 설정, 로컬 QA 환경 설정, 다른 경로에서 재실행한 결과. 모델 가중치와 비밀 값은 포함하지 않는다.
- 보고서: 실제 시작·종료·경과 시간, 사용 문서/질문 수, 실제 모델 생성·fallback·기권·오류 수, 검색/답변 정확도, 지연, 전후 차이, 남은 문제 3순위.

`docs/preprocessing_change_governance_ko.md`의 보호 범위 변경에는 관련 회귀 테스트와 PR 필수 항목을 준비한다. Code Owner 검토와 `preprocessing-reviewed` 라벨은 실제 사람 검토 절차로 남긴다. 이번 10시간 완료는 구현·로컬 검증·인계 상태이며 외부 게시·배포·병합 완료를 뜻하지 않는다.
