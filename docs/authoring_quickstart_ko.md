# 초보자용 규정 작성 빠른 시작

이 기능은 규정 파일이 아직 없을 때 초안을 만드는 로컬 작업공간입니다. 여기서
`내용 동결`한 결과는 기관 결재나 기존 RAG/MCP의 공식 승인이 아닙니다.

> 현재 P0는 실험 기능입니다. 자동화 테스트는 통과했지만 5명 이상 초보자를
> 대상으로 한 인간 사용성 출시 게이트는 아직 수행 전입니다.

## 처음 보는 사람은 이것만 기억하세요

- 이 화면은 원문 파일이 없을 때 초안을 시작하는 로컬 연습 공간입니다.
- `내용 동결`과 다운로드 파일은 모두 `공식 승인 아님`이며 바로 기존 RAG/MCP로 가지 않습니다.
- 막히면 새로 만들기보다 `작성 검사`, `저장`, `저장된 초안 패키지 다시 불러오기`를 먼저 확인하세요.

## 시작 전 알아둘 점

- 기본 템플릿과 검사는 외부 AI를 호출하지 않습니다.
- 작성 중인 내용은 기존 업로드·승인·색인 저장소와 분리됩니다.
- P0에서는 JSON 또는 Markdown 초안 패키지를 내려받을 수 있지만, 공식
  파이프라인으로 자동 전송하지 않습니다.
- 법적 적합성과 기관 결재는 담당자가 별도로 확인해야 합니다.

## 9단계 작성 흐름

1. 로컬 운영 화면에서 `✍️ 규정 새로 작성`을 선택합니다.
2. 기관과 작성 방식을 선택합니다. 처음 만드는 규정은 `신규 제정`, 기존 규정을
   바꾸는 작업은 `일부 개정` 또는 `전부 개정`입니다. P0는 기존 승인 규정
   카탈로그를 자동으로 불러오지 않으므로 개정 대상 정보는 직접 입력합니다.
3. 범용 규정, 위원회 운영, 업무 처리 절차 중 가장 가까운 템플릿을 고릅니다.
4. 규정명, 목적, 적용 범위, 근거, 담당부서와 시행 예정일을 입력합니다.
5. 각 조문의 쉬운말 안내를 보며 빈 내용을 채웁니다.
   P0에서는 조문 본문과 근거 연결만 편집할 수 있으며, 템플릿의 조문 번호·순서·
   제목·필수 여부는 일관된 안전 검사를 위해 서버가 고정합니다.
6. `작성 검사`에서 오류 위치와 수정 방법을 확인하고 오류를 모두 고칩니다.
   다른 법령·정관·조례의 조문을 인용할 때는 이름을 함께 적으세요. 예:
   `정관 제10조`, `「개인정보 보호법」 제15조`. `이 규정 제5조`처럼 현재 초안의
   조문을 가리키면 실제 제5조가 있어야 합니다.
7. `내용 확인 요청`을 눌러 확인 대기 상태로 바꿉니다. 로컬 1인 연습 화면에서는
   검토 시트를 다시 읽고 `연습용 자체 확인`과 사유를 입력한 뒤 내용 동결을 선택합니다.
   이 결과에는 `training_only=true`와 `공식 승인 아님` 표시가 계속 남습니다.
8. 동결된 연습용 개정본을 JSON 또는 Markdown 초안 패키지로 내보냅니다.
9. 브라우저를 닫았거나 다운로드에 실패했으면 `저장된 초안 패키지 다시 불러오기`를
   눌러 무결성을 다시 확인한 같은 파일을 받습니다. 새 개정본을 만들 필요가 없습니다.

내보낸 초안을 `새 개정본으로 다시 편집`하면 브라우저에 남은 이전 다운로드 파일은
즉시 제거됩니다. 다시 동결한 뒤에는 현재 동결 개정과 내용·파일 해시가 맞는 새
패키지를 만들어야 다운로드 버튼이 나타납니다.

화면은 각 단계에서 가장 먼저 해야 할 행동 또는 결정을 안내합니다. 경고가 있어도
수동 작성은 계속할 수 있지만, 오류 등급 항목이나 완료하지 않은 작성자 확인
목록이 남으면 내용 확인 요청과 동결은 진행할 수 없습니다.

보호된 2인 실무 흐름은 로컬 화면과 다릅니다. P0에는 자동 알림이나 결재선이
없으므로 별도 채널로 다른 담당자에게 알리고, 생성·수정·재개·확인 요청에 참여하지
않은 별도 확인자 계정이 보호 모드 API에서 특정 개정본을 동결해야 합니다. 로컬
연습용 자체 확인은 이 계정 분리를 대신하지 않습니다.

## 개정안을 만들 때

개정안에는 기존 규정을 식별할 규정명·버전 또는 시행일과 개정 사유가 필요합니다.
기존 승인 규정을 직접 덮어쓰지 않으며 별도 작성 프로젝트가 만들어집니다.

## 로컬 1인 연습

실무에서는 작성자와 확인자를 분리해야 합니다. 한 사람이 기능을 연습해야 하는
경우에만 `연습용 자체 확인`을 명시적으로 선택하고 사유를 적을 수 있습니다. 이
선택을 사용한 프로젝트에는 연습용 상태가 계속 남습니다. JSON에는
`training_only=true`, Markdown에는 `연습용 표시: 예`가 기록되며 두 형식 모두
`공식 승인 아님`을 표시합니다.

## 기관을 삭제할 때

기관 삭제 계획에는 같은 tenant·기관 프로필의 작성 초안 수도 함께 표시됩니다.
기본 삭제를 선택하면 작성 snapshot·event·내보내기도 함께 지우며, `데이터 남기기`
를 선택하면 보존합니다. 일부 파일 삭제가 실패하면 기관 프로필을 유지하고 다음
시도에서 남은 정리를 이어갑니다.

## 내보낸 뒤

초안 패키지를 기관의 법무·규정 담당자와 결재 절차에서 검토합니다. 공식 RAG/MCP
근거로 사용하려면 이후 별도의 전처리, 원문 대조, 사람 승인, 승인 해시 확인과
색인 절차를 모두 거쳐야 합니다.

여러 화면에서 같은 초안을 열어 저장 충돌이 나면 현재 미저장 문장을 먼저 복사한
뒤 `최신 개정 불러오기`를 사용합니다. 명시적으로 확인하기 전까지 브라우저 입력을
유지하며, 입력을 시작한 개정 번호도 자동으로 최신 번호에 합치지 않습니다. 충돌
상태에서는 저장·검사·상태 변경 버튼을 막아 최신본을 조용히 덮어쓰지 않습니다.
저장하지 않은 입력이나 충돌이 있는 상태에서 기관을 바꾸면 화면이 즉시 이동하지
않고, 필요한 문장을 복사하거나 현재 기관에서 저장한 뒤 떠날지 명시적으로 확인합니다.
초안 A에 저장하지 않은 값이 있는 채 초안 B를 선택하거나 새 초안을 만들어도,
같은 브라우저 세션에서는 초안·입력 구역별 임시 버퍼에 값이 남습니다. 기본정보만
먼저 저장해도 아직 저장하지 않은 조문·확인 목록은 버퍼와 기준 개정을 함께 유지합니다.
수정 요청 메모·자체 확인 사유·작성 중단 사유도 같은 방식으로 임시 보존하지만,
중단·동결 같은 중요한 확인 체크는 돌아왔을 때 다시 선택해야 합니다.
실수로 반대 결정을 누르지 않도록 작성 중단을 입력하는 동안에는 `조문 작성 시작`이,
수정 요청을 입력하는 동안에는 연습용 동결이 서로 잠깁니다. 결정을 바꾸려면
`작성 중단 입력 지우기` 또는 `검토 결정 입력 지우기`로 기존 사유와 확인을 먼저
초기화하세요.
다만 이 버퍼는 서버 저장이 아니므로 브라우저 탭을 닫거나 세션이 만료되기 전에 각
구역의 `저장` 버튼을 눌러야 합니다. 현재 기관의 선택 해제된 초안에 미저장 값이
있어도 기관 전환 확인이 표시됩니다.

P0 Streamlit 화면은 신뢰할 수 있는 PC의 local-only 모드에서만 사용합니다. 보호
배포에서는 작성 API만 제공하며, `ENABLE_REGULATION_AUTHORING=true`를 명시하기
전에 인증, 테넌트 격리, 감사 로그, 작성자·확인자 계정 분리와 authoring 디렉터리
권한을 확인합니다. 인증된 공유 작성 UI는 P2 범위입니다.
