# 공공기관 규정 로컬 AI 플랫폼 전환 방향

## 결정

이 프로젝트는 MCP 전용 도구가 아니라 **승인된 공공기관 규정으로 폐쇄망 로컬 AI를 구성하는 플랫폼**으로 확장한다.

- 규정 전처리·구조화·품질검사·사람 승인·테넌트 격리는 기존 핵심 엔진으로 유지한다.
- 로컬 RAG 질의응답을 운영자가 직접 사용하는 기본 제품 흐름으로 승격한다.
- MCP는 제거하지 않고, ChatGPT·Claude·Codex·기관 AI가 같은 승인된 RAG 엔진에 연결하는 선택적 외부 인터페이스로 유지한다.
- 1차 로컬 답변 모델은 Qwen3 8B로 고정한다. Ollama 기본 식별자는 `qwen3:8b`이며, llama.cpp는 Qwen3 8B GGUF 또는 동일 계열의 기관 보유 모델 파일을 사용한다.
- 모델 가중치와 기관 문서는 저장소에 포함하지 않는다. 로컬 모델 런타임과 데이터 디렉터리는 설치·운영 환경에서 관리한다.

## 이미지와 현재 저장소의 대응

이미지의 두 시리즈는 현재 코드와 다음처럼 연결된다.

| 이미지의 구성 | 현재 저장소 | 전환 시 역할 |
| --- | --- | --- |
| 규정 전처리기 | `app/parsers`, `app/processors`, `app/services/processing_service.py` | 규정 구조화 및 품질 게이트 |
| 승인된 VectorDB | `app/services/approval_governance.py`, `app/ingestion`, `app/retrieval` | 승인·최신본·기관 범위가 적용된 검색 기반 |
| Hybrid 검색·재랭킹 | `app/retrieval`, `app/services/regulation_rag_runtime.py` | 검색 품질과 조문 단위 근거 선택 |
| 로컬 LLM | `app/rag/local_llm.py`, `/api/rag/chat` | Ollama·llama.cpp·호환 로컬 엔드포인트를 통한 답변 생성 |
| MCP 연결 | `app/mcp_server`, `app/api` | 같은 RAG 근거를 외부 AI 클라이언트에 제공하는 어댑터 |

현재 저장소는 이미 로컬 LLM 연결 지점을 갖고 있다. 따라서 새 제품을 처음부터 만들기보다, MCP 중심의 설명과 화면을 로컬 AI 중심으로 재배치하는 것이 기술 부채와 회귀 위험이 작다.

## MCP와 로컬 LLM의 관계

둘은 대체 관계가 아니다.

```text
규정 파일
  -> 전처리/구조화
  -> 사람 검수/승인
  -> 승인된 최신본 RAG 인덱스
       -> 로컬 QA 화면 -> 로컬 LLM -> 답변 + 근거 조문
       -> MCP 서버    -> ChatGPT/Claude/Codex/기관 AI
```

답변의 신뢰 경계는 LLM이 아니라 승인된 검색 결과와 인용 정책이 담당한다. LLM은 검색된 근거를 읽기 쉬운 답변으로 정리하는 계층이며, 근거가 없으면 답변하지 않는 정책을 따라야 한다.

## 새 프로젝트 폴더를 만들지 않는 이유

현 단계에서는 별도 프로젝트 폴더를 만들지 않는다.

현재 저장소에 이미 다음이 구현되어 있기 때문이다.

- PDF/HWP/HWPX/DOCX 파싱과 규정 계층·표 처리
- 승인 전용 색인과 승인 저널
- 기관 프로필·tenant 범위·보안 등급 필터
- 하이브리드 검색과 구조화된 조문 조회
- 로컬 LLM 호출 및 추출식 답변 fallback
- MCP stdio/HTTP 서버와 연결 검증

이 기반을 새 폴더에서 복제하면 승인 정책, 최신본 판정, 테넌트 격리, 인용 규칙이 두 구현으로 갈라질 위험이 있다. 먼저 같은 저장소에서 제품 경계를 분리하고, 실제 배포 시에만 런타임 패키지를 별도 배포물로 분리한다.

다음 조건이 충족될 때만 별도 저장소를 검토한다.

- 로컬 모델 설치기·GPU 런타임·대형 바이너리 때문에 기본 전처리 설치가 과도하게 무거워질 때
- 로컬 QA 데스크톱 앱이 규정 엔진과 독립적인 출시 주기를 가져야 할 때
- 기관별 비공개 배포 코드가 공개 소스 정책과 분리되어야 할 때
- 외부 모델 라이선스나 배포 제약이 공개 저장소의 선택적 의존성으로 해결되지 않을 때

## 권장 모듈 경계

기존 호환성을 유지하면서 다음 순서로 정리한다.

```text
app/rag/
  local_llm.py              # 기존 호환 facade
  backends/                 # extractive, ollama, llama.cpp adapter
  answer_policy.py          # 근거 부족·거부·출력 형식 정책
  answer_service.py         # search -> context -> answer -> citations

app/retrieval/
  ...                       # 승인·기관·최신본 범위가 적용된 검색

frontend/
  ...                       # 전처리/승인 화면
  local_qa/                 # 로컬 QA 운영 화면과 모델 상태 진단

scripts/
  ...
  local_llm_doctor.py       # 모델·endpoint·context·오프라인 상태 점검
```

첫 구현에서 모델 학습이나 파인튜닝은 하지 않는다. 기존의 로컬 엔드포인트 계약을 유지하고, 설치된 모델을 선택하는 기능과 운영 진단을 먼저 만든다. 기본 실행 프로필은 다음 세 가지로 둔다.

1. `extractive`: 모델 없이 근거 문장을 구조화해 답변하는 안전한 기본값
2. `ollama + qwen3:8b`: 1차 운영 표준 로컬 모델 프로필
3. `llama-cpp + Qwen3 8B GGUF`: 외부 서버 의존을 줄이고 모델 파일을 직접 관리하는 고급 프로필

## 구현 순서

### 1단계 — 제품 흐름 전환

- 첫 화면의 중심을 “MCP 생성”에서 “규정 등록 → 승인 → 로컬 질의응답”으로 전환한다.
- 현재 MCP 단계는 “외부 AI 연결이 필요한 경우”의 선택 흐름으로 이동한다.
- 모델이 없어도 전처리·승인·검색·추출식 답변까지 동작하도록 유지한다.

### 2단계 — 로컬 모델 운영 계층

- Ollama/llama.cpp 연결 상태, 선택 모델, 응답 시간, context 제한을 한 화면에서 진단한다.
- 모델 자동 다운로드는 기본 비활성화한다.
- 외부 endpoint는 localhost만 허용하고, 기관 문서가 외부 API로 전송되지 않도록 현재 보안 정책을 유지한다.
- 모델이 반환한 인용을 신뢰하지 말고, 시스템이 검색 결과에서 citation을 다시 구성한다.

### 3단계 — 검색 품질 고도화

- 현재 `local-hash-embedding-v1`은 결정적 fallback으로 남긴다.
- 의미 기반 로컬 embedding은 선택적 backend로 추가하고, 기존 색인과 모델 버전을 메타데이터로 구분한다.
- 모델 변경 시 전체 재색인과 검색 회귀 검사를 요구한다.

### 4단계 — 답변 품질 게이트

답변은 다음 계약을 만족해야 한다.

- 승인된 청크만 context에 들어간다.
- 기관·부서·보안 등급·최신본 필터를 검색 전에 적용한다.
- 답변마다 조문·문서·페이지 등 시스템이 확인한 근거를 붙인다.
- 근거가 부족하면 “확인할 수 없음”으로 답하고 추측하지 않는다.
- LLM 장애 시 추출식 답변 또는 명확한 장애 상태를 반환한다.
- 질의, 검색 결과, 모델, 답변, 인용의 trace를 남기되 로컬 경로·비공개 운영 정보는 외부 응답에 넣지 않는다.

## 제품 명칭과 저장소 전략

당장 저장소 이름과 MCP 관련 코드를 바꾸지 않는다. 공개 저장소의 기존 사용법과 릴리스 검증이 MCP 명칭을 전제로 하고 있기 때문이다.

제품 설명은 다음처럼 바꾼다.

> 공공기관 규정을 승인 가능한 구조 데이터로 바꾸고, 폐쇄망 로컬 AI가 근거 조문과 함께 답변하도록 만드는 규정 지식 플랫폼. 필요하면 MCP로 외부 AI에도 연결한다.

즉, **제품의 중심은 Local Regulation AI**, **연결 방식 중 하나가 MCP**라는 순서로 전환한다. 이 문서는 이후 README·운영 UI·PRD를 수정할 때의 기준으로 사용한다.

## 완료 기준

다음 흐름이 한 저장소에서 재현되면 1차 전환이 완료된 것으로 본다.

1. 규정 파일을 등록한다.
2. 구조·표·조문 단위 결과를 사람이 검수하고 승인한다.
3. 승인된 최신 규정만 로컬 검색 인덱스에 반영된다.
4. 모델이 없어도 추출식 근거 답변이 나온다.
5. Ollama 또는 llama.cpp를 연결하면 같은 근거로 자연어 답변이 나온다.
6. 답변에는 시스템이 검증한 근거 조문이 포함된다.
7. 같은 승인 데이터가 필요할 때 MCP 도구로도 조회된다.
8. tenant·기관 범위 밖의 문서와 미승인 청크는 두 경로 모두에서 보이지 않는다.
