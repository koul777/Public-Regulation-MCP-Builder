# 로컬 운영자 화면

주 화면은 파일 업로드 → 전처리 → 검수·승인 → 승인된 내용 검색 순서로 사용합니다.
직접 규정 제정·집필 화면, 시작 화면 바로가기와 사이드바 메뉴는 제공하지 않습니다.
예전 작성 화면 주소나 세션 탐색 값은 시작 화면으로 돌아옵니다.
퇴역한 nav 쿼리만 제거하므로 다른 쿼리를 보존하고 이후 업로드 단계로 이동할 수 있습니다.
기존 초안 저장소와 API는 유지하며 저장된 초안 데이터를 삭제하지 않습니다.
ENABLE_REGULATION_AUTHORING 및 Compose의 STREAMLIT_ENABLE_REGULATION_AUTHORING은
기본 false입니다. 명시적으로 API를 켜도 운영자 화면의 집필 메뉴는 생기지 않습니다.

통합 규정집의 별표 뒤 규정 경계가 불명확한 조항은 승인할 수 없습니다.
단일 규정, 파일 전체, 초보자 일괄 승인과 여러 문서 승인 모두 대상 전체를 먼저
검사합니다. 차단된 요청은 수정 내용을 저장하거나 승인 증빙·승인 기록·색인을
만들기 전에 중단합니다. 여러 문서 중 뒤쪽 문서가 차단되어도 앞쪽 문서부터
저장하지 않습니다. 일반 파서·표 경고의 검수 확인 및 미검수 승인 감사 사유 정책은
그대로 적용됩니다.

차단 안내의 ‘같은 원본 다시 올려 전처리하기’를 눌러 업로드 단계로 이동합니다.
최신 파서가 적용된 앱에서 같은 원본 파일을 다시 올리고 전처리 결과를 검수합니다.
경계 차단이 남은 완료 결과는 캐시에서 재사용하지 않습니다. 새 업로드는 별도 문서 ID와
파일 경로의 초안을 만들므로 기존 원본·승인 기록·색인을 덮어쓰지 않습니다. 파서 설정은
자동 변경하지 않습니다. 다시 분석해도 경계가 불명확하면 규정별로 분리한 파일을 따로 올립니다.
기존 Kordoc 안전 재전처리는 같은 원본 해시의 초안을 재사용할 수 있으므로,
반환된 초안의 경계 차단을 다시 검사합니다. 차단이 남아 있으면 해결 완료로
표시하거나 작업 문서를 그 초안으로 교체하지 않습니다. 자동으로 원본을 덮어쓰거나
파서 설정을 바꾸지 않습니다.
